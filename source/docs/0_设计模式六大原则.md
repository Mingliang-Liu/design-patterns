- 1、**开闭原则**（Open-Closed Principle）

对扩展开放，对修改关闭。软件应能通过扩展新功能，而非修改已有代码来适应变化。实现这一原则的核心在于使用抽象（接口或基类）定义稳定的行为。

- 2、**里氏替换原则**（Liskov Substitution Principle）

任何基类出现的地方，子类都应该可以替代。只有当派生类能完全替代基类时，继承才有意义。这一原则保证了多态的正确性，是开闭原则的重要补充。

- 3、**依赖倒置原则**（Dependency Inversion Principle）

高层模块不应依赖低层模块，两者都应依赖抽象。具体实现应依赖接口或抽象类，而不是直接依赖具体类。该原则使系统更易于扩展与测试。

- 4、**接口隔离原则**（Interface Segregation Principle）

一个类不应该依赖它不需要的接口。应将大接口拆分为多个更小、更专用的接口，以降低耦合、提高灵活性。

- 5、**最少知道原则**（Law of Demeter）

又称"迪米特法则"：一个对象应尽量减少与其他对象的交互。换言之，一个类应只了解与自己直接相关的对象，从而降低系统复杂度。

- 6、**合成复用原则**（Composite Reuse Principle）

优先使用组合或聚合关系来实现复用，而非继承。继承会造成强耦合，而组合能在运行时灵活替换依赖，实现更优雅的结构设计。

以下是针对这六大原则的 Python 代码示例：


### 1. 开闭原则 (OCP)
**核心：** 增加新功能时，不要改动原有类，而是增加新类。

```python
from abc import ABC, abstractmethod

# 抽象基类定义稳定行为
class Shape(ABC):
    @abstractmethod
    def area(self):
        pass

class Rectangle(Shape):
    def __init__(self, w, h):
        self.w = w
        self.h = h
    def area(self):
        return self.w * self.h

# 扩展新功能（圆形）时，无需修改 Shape 或 Rectangle
class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius
    def area(self):
        return 3.14 * self.radius ** 2

def calculate_total_area(shapes):
    return sum(shape.area() for shape in shapes)
```

### 2. 里氏替换原则 (LSP)
**核心：** 子类不能破坏父类的原有功能。最经典的违例就是“正方形继承长方形”。

```python
class Bird:
    def fly(self):
        return "I am flying"

# 错误示例：企鹅不会飞，替换父类会报错或逻辑异常
# class Penguin(Bird):
#     def fly(self):
#         raise Exception("Cannot fly")

# 正确做法：拆分抽象
class FlyingBird(Bird):
    def fly(self):
        return "I am flying"

class Penguin(Bird):
    def swim(self):
        return "I am swimming"
```

### 3. 依赖倒置原则 (DIP)
**核心：** 面向接口编程，不要面向实现编程。

```python
from abc import ABC, abstractmethod

# 抽象接口
class SwitchableDevice(ABC):
    @abstractmethod
    def turn_on(self): pass

class LightBulb(SwitchableDevice):
    def turn_on(self): print("灯亮了")

class Fan(SwitchableDevice):
    def turn_on(self): print("风扇转了")

# 高层模块依赖抽象，而不是具体的 LightBulb
class RemoteControl:
    def __init__(self, device: SwitchableDevice):
        self.device = device
    
    def press_button(self):
        self.device.turn_on()
```

### 4. 接口隔离原则 (ISP)
**核心：** 客户端不应被迫依赖它不使用的方法。Python 中常用“多重继承”来实现。

```python
class Printer(ABC):
    @abstractmethod
    def print_doc(self): pass

class Scanner(ABC):
    @abstractmethod
    def scan_doc(self): pass

# 基础打印机只实现打印
class BasicPrinter(Printer):
    def print_doc(self):
        print("Printing...")

# 多功能打印机实现多个接口
class SmartPrinter(Printer, Scanner):
    def print_doc(self):
        print("Printing...")
    def scan_doc(self):
        print("Scanning...")
```

### 5. 最少知道原则 (LoD)
**核心：** 只与你的直接朋友交谈。

```python
# 违背原则：Manager 通过职员去获取职员的电脑信息（跨级调用）
# manager.staff.computer.get_cpu_info()

# 遵循原则：Manager 只管问职员，职员自己内部处理
class Computer:
    def get_info(self): return "CPU i9"

class Staff:
    def __init__(self):
        self.computer = Computer()
    
    def report_specs(self):
        return self.computer.get_info()

class Manager:
    def check_staff(self, staff: Staff):
        # Manager 只直接联系 Staff 对象
        print(staff.report_specs())
```

### 6. 合成复用原则 (CRP)
**核心：** 想要“汽车”有“引擎”的功能，不要让汽车继承引擎，而是把引擎放进汽车里。

```python
class Engine:
    def start(self):
        return "Engine started"

# 推荐：组合（Composition）
class Car:
    def __init__(self):
        self.engine = Engine() # 汽车“有一个”引擎
        
    def move(self):
        status = self.engine.start()
        print(f"Car is moving: {status}")

# 不推荐：继承（Inheritance）
# class Car(Engine): ... (汽车“是一个”引擎，逻辑荒谬)
```

### 总结表

| 原则 | 关键词 | 核心目的 |
| :--- | :--- | :--- |
| **OCP** | 扩展/修改 | 提高代码可维护性 |
| **LSP** | 替换/继承 | 保证继承体系的稳健 |
| **DIP** | 抽象/细节 | 解耦高层与低层模块 |
| **ISP** | 精简/专业 | 避免接口臃肿 |
| **LoD** | 解耦/私密 | 降低类之间的相互影响 |
| **CRP** | 组合/继承 | 增加设计的灵活性 |
