# 03 单例模式（Singleton Pattern） 
LML一句话总结：  
**确保一个类只有一个实例，并提供一个全局访问点来获取这个实例**

![单例模式](../../_static/images/03_singleton.png)

## 使用场景
- 配置管理器：整个应用程序共享同一套配置
- 数据库连接池：避免重复创建连接，节省资源
- 日志记录器：确保所有日志都写入同一个文件
- 缓存系统：统一管理缓存数据

## 实现方式
方法一：使用模块（最简单的方式）
```
# 新建一个模块，比如
# singleton_module.py

class DatabaseConnection:
    def __init__(self):
        self.connection_string = "database://localhost:5432/mydb"
        print("数据库连接已创建")
    
    def query(self, sql):
        return f"执行查询: {sql}"

# 创建单例实例
db_instance = DatabaseConnection()

# 在其他文件中使用，就只有一个实例：
# from singleton_module import db_instance
# result = db_instance.query("SELECT * FROM users")
```

方法二：使用 __new__ 方法
```
class Singleton:
    _instance = None
    
    def __new__(cls, *args, **kwargs):
        # 如果实例不存在，则创建新实例
        if not cls._instance:
            cls._instance = super().__new__(cls)
            print("创建新的单例实例")
        else:
            print("返回已存在的单例实例")
        return cls._instance
    
    def __init__(self, name):
        # 注意：__init__ 每次都会被调用
        self.name = name
        print(f"初始化实例，名称: {name}")

# 测试代码
print("=== 测试单例模式 ===")
s1 = Singleton("第一个实例")
s2 = Singleton("第二个实例")

print(f"s1 的 ID: {id(s1)}")
print(f"s2 的 ID: {id(s2)}")
print(f"s1 和 s2 是同一个对象吗？ {s1 is s2}")
print(f"s1 名称: {s1.name}")
print(f"s2 名称: {s2.name}")  # 注意：这里会显示"第二个实例"
```

方法三：使用装饰器
```
def singleton(cls):
    """单例装饰器"""
    instances = {}
    
    def get_instance(*args, **kwargs):
        # 如果该类还没有实例，则创建新实例
        if cls not in instances:
            instances[cls] = cls(*args, **kwargs)
            print(f"创建 {cls.__name__} 的新实例")
        else:
            print(f"返回已存在的 {cls.__name__} 实例")
        return instances[cls]
    
    return get_instance

@singleton
class ConfigurationManager:
    def __init__(self):
        self.settings = {}
        self.load_default_settings()
    
    def load_default_settings(self):
        self.settings = {
            "app_name": "我的应用",
            "version": "1.0.0",
            "debug_mode": True
        }
    
    def get_setting(self, key):
        return self.settings.get(key)
    
    def set_setting(self, key, value):
        self.settings[key] = value

# 测试代码
print("\n=== 测试装饰器单例 ===")
config1 = ConfigurationManager()
config2 = ConfigurationManager()

config1.set_setting("theme", "dark")
print(f"config1 主题: {config1.get_setting('theme')}")
print(f"config2 主题: {config2.get_setting('theme')}")  # 两个实例共享同一配置
```
方法四：使用元类
```
class SingletonMeta(type):
    """单例元类"""
    _instances = {}
    
    def __call__(cls, *args, **kwargs):
        # 如果该类还没有实例，则创建新实例
        if cls not in cls._instances:
            instance = super().__call__(*args, **kwargs)
            cls._instances[cls] = instance
            print(f"元类：创建 {cls.__name__} 的新实例")
        else:
            print(f"元类：返回已存在的 {cls.__name__} 实例")
        return cls._instances[cls]

class Logger(metaclass=SingletonMeta):
    def __init__(self, log_file="app.log"):
        self.log_file = log_file
        self.logs = []
        print(f"日志器初始化，文件: {log_file}")
    
    def log(self, message):
        log_entry = f"[{self.get_timestamp()}] {message}"
        self.logs.append(log_entry)
        print(f"记录日志: {log_entry}")
        return log_entry
    
    def get_timestamp(self):
        from datetime import datetime
        return datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    
    def get_logs(self):
        return self.logs.copy()

# 测试代码
print("\n=== 测试元类单例 ===")
logger1 = Logger("application.log")
logger2 = Logger("different.log")  # 这个文件名会被忽略

logger1.log("系统启动")
logger2.log("用户登录")

print(f"logger1 日志数量: {len(logger1.get_logs())}")
print(f"logger2 日志数量: {len(logger2.get_logs())}")
print(f"是同一个日志器吗？ {logger1 is logger2}")
```

## 四种实现方式对比

### 1. 模块导入法
这是 Python 官方文档暗示的最推荐方式。
*   **优点**：
    *   **天然单例**：Python 模块在第一次导入时会执行并生成 `.pyc`，后续所有 `import` 都直接指向内存中的同一对象。
    *   **线程安全**：由 Python 解释器在导入机制级别保证，无需自己写锁。
*   **缺点**：
    *   **不够灵活**：不支持延迟初始化（除非你在函数内 `import`）。
    *   **无法传参**：实例在模块加载时就定死了。

### 2. `__new__` 方法  
通过修改类的实例化逻辑来控制对象生成。
*   **优点**：
    *   **符合直觉**：看起来最像传统的面向对象单例，且支持继承。
*   **缺点**：
    *   **`__init__` 重复调用陷阱**：正如你在注释中所写，即使返回的是同一个对象，Python 依然会再次调用 `__init__`。这意味着如果初始化逻辑很重（比如连接数据库），每次 `s2 = Singleton()` 都会重新初始化一遍，这通常不是我们想要的。

### 3. 装饰器
*   **优点**：
    *   **按需使用**：非常灵活，可以随时给任何现有的类加上单例特性。
    *   **延迟实例化**：只有在第一次调用类时才会创建对象。
*   **缺点**：
    *   **身份危机**：装饰后的类其实是一个函数，如果你需要使用 `classmethod` 或 `staticmethod`，或者依赖 `type(obj)` 的判断，可能会出现偏差。

### 4. 元类
*   **优点**：
    *   **解决 `__init__` 问题**：元类的 `__call__` 拦截了整个创建过程。如果实例已存在，它连 `__init__` 都不会让它跑，完美解决了 `__new__` 的尴尬。
    *   **高度统一**：在大型框架（如 Django/Flask 内部）中，这种方式最能保持类行为的一致性。
*   **缺点**：
    *   **学习曲线**：对于不熟悉元类机制的开发者来说，这简直是“黑魔法”。

## 总结

在真实的项目开发中，建议遵循以下原则：

1.  **首选：模块导入**。如果你只是需要一个全局的工具类（如 `config` 或 `db`），直接在模块里实例化。简单、安全、高效。
2.  **次选：装饰器**。如果你希望在不同的类上复用单例逻辑，且不介意它在技术上变成了一个包装函数，装饰器是最轻便的选择。
3.  **大招：元类**。如果你正在编写一个**底层框架或类库**，需要严格控制实例化逻辑，且必须保证类依然是“类”，请直接使用元类。
4.  **避坑：`__new__`**。除非你有特殊需求（比如要在实例创建前进行极其底层的拦截），否则一般不推荐，因为处理 `__init__` 重复执行的问题会让代码变得很丑。

## 进阶：双重检查锁 (Double-Checked Locking)
在上面示例中，**装饰器**和**元类**的实现都是**非线程安全**的。如果两个线程同时进入 `if cls not in instances` 判断，可能会创建两个实例。

在多线程环境下，生产级代码通常会加上锁：
```python
import threading

class SingletonMeta(type):
    _instances = {}
    _lock = threading.Lock() # 加入锁

    def __call__(cls, *args, **kwargs):
        with cls._lock: # 确保创建过程原子化
            if cls not in cls._instances:
                instance = super().__call__(*args, **kwargs)
                cls._instances[cls] = instance
        return cls._instances[cls]
```

## 实现示例

### 1. 配置管理器 (ConfigManager)
```python
import json

class ConfigManager(metaclass=SingletonMeta):
    def __init__(self):
        self._config = {}
        self._listeners = []
        self._schema = {"app_name": str, "version": str, "port": int}

    def add_listener(self, callback):
        self._listeners.append(callback)

    def load_from_json(self, file_path):
        with open(file_path, 'r') as f:
            data = json.load(f)
            if self._validate(data):
                self._config = data
                self._notify()

    def _validate(self, data):
        # 基础校验：检查键是否存在且类型正确
        for key, expected_type in self._schema.items():
            if key not in data or not isinstance(data[key], expected_type):
                raise ValueError(f"配置项 {key} 无效")
        return True

    def _notify(self):
        for listener in self._listeners:
            listener(self._config)

    def get(self, key, default=None):
        return self._config.get(key, default)


# 使用
# 配置监听测试
def on_config_change(new_cfg):
    print(f"📢 监听到配置变更！新端口: {new_cfg.get('port')}")

cfg = ConfigManager()
cfg.add_listener(on_config_change)
# 假设存在 config.json: {"app_name": "Test", "version": "1.0", "port": 8080}
# cfg.load_from_json("config.json")
```

### 2. 数据库连接池 (DBConnectionPool)
重点在于资源的统一分配与回收感知

```python
class DBConnectionPool(metaclass=SingletonMeta):
    def __init__(self, size=5):
        self.size = size
        self._pool = [f"Connection-{i}" for i in range(size)]
        print(f"池化层：已初始化 {size} 个数据库连接")

    def acquire(self):
        if not self._pool:
            raise Exception("连接池已耗尽")
        conn = self._pool.pop()
        print(f"分配连接: {conn}")
        return conn

    def release(self, conn):
        self._pool.append(conn)
        print(f"回收连接: {conn}")
```

### 3. 日志记录器 (Logger)
通过单例确保 I/O 操作不会因为多个对象竞争文件句柄而产生冲突。

```python
import datetime

class Logger(metaclass=SingletonMeta):
    def __init__(self):
        self.file_name = f"app_{datetime.date.today()}.log"
        print(f"日志系统启动，目标文件: {self.file_name}")

    def log(self, level, message):
        timestamp = datetime.datetime.now().strftime("%H:%M:%S")
        entry = f"[{timestamp}] [{level}] {message}\n"
        # 实际生产环境应使用 logging 库，此处仅演示单例保护
        with open(self.file_name, "a", encoding="utf-8") as f:
            f.write(entry)
```

### 4. 缓存系统 (CacheSystem)
包含了TTL (Time To Live) 过期机制。

```python
import time

class CacheSystem(metaclass=SingletonMeta):
    def __init__(self):
        self._storage = {} # 格式: {key: (value, expire_at)}

    def set(self, key, value, ttl=None):
        expire_at = time.time() + ttl if ttl else None
        self._storage[key] = (value, expire_at)
        print(f"缓存设置: {key} (TTL: {ttl}s)")

    def get(self, key):
        if key not in self._storage:
            return None
        
        value, expire_at = self._storage[key]
        # 检查是否过期
        if expire_at and time.time() > expire_at:
            self.delete(key)
            return None
        return value

    def delete(self, key):
        self._storage.pop(key, None)

    def clear(self):
        self._storage.clear()

# 缓存测试
cache = CacheSystem()
cache.set("session_id", "ABC-123", ttl=2)
print(f"立即获取: {cache.get('session_id')}")
time.sleep(2.1)
print(f"2秒后获取: {cache.get('session_id')}") # 应该返回 None
```
